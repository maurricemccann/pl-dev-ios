# Lane D: the code art, native

Worktree `C:\dev\pl-dev-ios--codeart`, branch `lane-codeart`. All new code is in `PLDev/Sections/CodeArt/` (14 files) plus a test folder `codeart-tests/` at the repo root (outside every target). No shared file was edited.

## What was built

**The runtime (his piece code runs unchanged).**
- `codeart-tests/prelude.js` (embedded as `CanvasPrelude.swift`, generated by `gen_prelude.py`) gives JavaScriptCore the browser surface the six bundles expect: `window`, `document`, `Canvas`/`OffscreenCanvas`, `CanvasRenderingContext2D` (every method and property the pieces use: paths, arcs, beziers, ellipses, roundRect, fill/stroke/clip with rules, gradients, patterns with `setTransform`, transforms, save/restore, globalAlpha, 26 composite modes, shadows, line caps/joins/dash, text, `measureText`, `drawImage` of canvases and images, `getImageData`/`putImageData`/`createImageData`, `isPointInPath`/`isPointInStroke`, `filter: blur()`), `Path2D` from SVG path data, `Image`, `ImageData`, `DOMParser` (enough SVG for his comps), `DOMMatrix`, `fetch`, timers, `performance.now`, `window.__VJ_AUDIO`, a WebGL stub (so `shaderPiece()` runs unchanged), and the piece harness (`make` once, warm, then `draw`, as CurateDeck's `LivePieceCanvas` does).
- Canvas calls are recorded as numbers into one `Float64Array` and sent to native in a single flush per canvas (a frame costs a handful of bridge calls, not thousands).
- `CanvasSurface.swift` replays that stream on a Core Graphics bitmap (premultiplied RGBA, y-down like the browser). `SVGPath.swift` parses `d` (all commands including arcs, parsed once and kept). `PieceRuntime.swift` is the one JavaScript queue, the bundle loader (from the gallery's `/scripts/`, kept on the phone, refreshed when a day old, so it works offline) and the instance API.
- **Shaders:** `PieceShader.swift` translates each `shaderPiece` GLSL fragment to a Metal fragment shader at run time (same uniforms: `u_time u_res u_bass u_mid u_high u_beat u_gold u_ink u_bg`), renders it, and the pixels land in the piece's canvas, which the piece then `drawImage`s as in the browser. This covers all five house shaders (goldfog, plasma, tunnel, oil, prism) and any shader a Forge run writes in the same dialect. A fragment that cannot compile shows the piece's ground colour, never a crash.
- **Audio:** `VJAudio.swift`: microphone or a looped track through AVAudioEngine, a 2048-point vDSP FFT with the browser AnalyserNode's maths (Hann window, 0.82 smoothing, -100 to -30 dB to a byte) and VJEngine's band split (bass < 200 Hz, mid < 4 kHz, high < 12 kHz, gain 1.7), the same bass-transient beat detector, and tap tempo. It feeds `window.__VJ_AUDIO` every frame.

**The rooms.**
- `NativeCurvesRoom` (`CurvesRoom.swift`): every code piece as a tile; the first six on screen run live at 30 fps as you scroll; the gallery's own sets (Curated, Canon, Wave one, Wave two, Written by the board, The archive) from a menu; search by name, id or tag; liked-only; touch and hold to like (optimistic, comes back with a plain line if the gallery refuses); full-screen `PieceStage` (swipe for the next, tap for the bars, heart, share link, the code through the Library's `SourceView`, a sound menu: microphone, Helium, Fractal, or a file from the phone).
- `LivePieceCard` (`PieceViews.swift`): the code card for Curate and the Library, with the web card's fallbacks: a piece that averages over 40 ms a frame plays its recorded clip (from `cinematic/manifest.json`, with the speaker toggle), else its capture; a piece that draws one flat colour for 300 frames shows its still.
- `NativeVJRoom` (`VJViews.swift`, `VJModel.swift`, `VJEngine.swift`): the instrument at `/live`. Full-bleed Metal output; deck A and an optional deck B (two pieces, not one drawn twice); the four blend modes and opacity B; the eight effects on Metal (zoom, kaleido, mirror, pixelate, glitch, rgbshift, strobe, invert: a direct port of `VJEffects.ts`); speed/zoom/tilt/warm/strength knobs; bass/mid/high reactivity; the 5-by-5 modulation matrix (bass, mid, high, beat, tempo-synced LFO into speed, zoom, tilt, warm, blend); six scene pads; eight sets (presets) kept on the phone; tap tempo; auto-advance every 4/8/16/32 beats; the eight-step sequencer that moves on the beat; the 0.9 s dissolve between pieces; the piece browser; **SNAP** (a still, to the share sheet, which has Save Image, and filed to the vault's `snaps/` through `api/vault/upload` as `/live` does); **REC** (AVAssetWriter, H.264, to the share sheet, which has Save Video).
- `NativeForgeRoom` (`ForgeRoom.swift`): describe a piece, Generate (`api/vj-coder` with the same contract text `/forge` sends), edit the code, Run (the new piece registers in the same runtime and runs in a live preview), Copy, Start over. With no sound source the preview uses a gentle signal of its own.
- Tips (`CodeArtTips.swift`): one for the hold-to-like, one for the swipe, one for the VJ gestures. The rooms follow DESIGN.md: segmented control under the title for the rack (no second tab bar), grouped forms, `ResultLine` for results, `ContentUnavailableView` for empty and failed, haptics on every change, optimistic likes.

## Unproven (nothing here has run on a device)

Look at these first when he tests:
1. **Every piece's first frame.** Core Graphics is not Chrome: anti-aliasing, text metrics and gradient interpolation differ a little. If a piece looks wrong, `PieceDisplay` shows the web card's fallbacks, and `DebugBridge.lines` keeps the last 60 script errors and shader failures.
2. **Shader pieces (the five).** The GLSL-to-Metal translation was read, not compiled (there is no Metal compiler on this PC). The uniforms are locals of `main`, so a helper function that reads `u_*` directly will not compile; none of the five does. A failure shows the ground colour and writes a line to `DebugBridge`.
3. **Shadow direction.** `shadowOffsetY` is sent to Core Graphics with its sign flipped (my reading of how Core Graphics treats offsets under a flipped matrix). If shadows fall upward, remove the minus in `CanvasSurface.applyShadow`.
4. **Frame rate of the heavy pieces** (the 40 ms rule moves them to their recorded clip, as the web does). 60 fps for the light ones is expected; the grid caps live tiles at six at 30 fps.
5. **VJ on device:** the Metal layer, the beat detector with real music, REC file validity, SNAP to the vault (cookie), the 0.9 s dissolve.
6. **Audio:** microphone permission flow and the track loop after the route changes (a call, a headset).
7. **JavaScript memory.** Native bitmaps are invisible to JavaScript's collector, so the runtime forces a collection after 160 MB of new canvases; watch a piece that builds many offscreen canvases per frame.
8. **First launch with no network:** the bundles are not on the phone yet and the room says so with a Try again.
